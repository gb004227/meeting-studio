# 听会 · Meeting Studio

Windows 会议录音与转写桌面软件，支持实时录音和音频/视频文件导入。每种模式均可选择豆包云端或 MOSS 本地，使用同一套说话人编辑、原文校对、会议纪要和行动项界面。

## GitHub 下载

到 [Releases](https://github.com/gb004227/meeting-studio/releases/latest) 下载同一版本的两个独立 ZIP：

- `TingHui-0.1.2-Windows-x64-program.zip`：程序、独立 Python 和 C++ 运行库。
- `TingHui-0.1.2-models.zip`：MOSS、实时字幕与说话人模型。

解压程序包，再将模型包解压得到的整个 `models` 文件夹放进程序目录的 `resources`。双击 `听会.exe` 即可使用；新电脑无需安装 Python、Node.js、uv 或重新下载模型。建议预留至少 10GB 空间。完整步骤见 [GitHub 安装说明](GITHUB安装说明.md)。

## 启动

- 桌面发布包：双击目录中的 `听会.exe`；在源码项目中，它位于 `release/听会 Windows/听会.exe`。该目录包含主程序自己的 Python 运行环境，移动时请保留整个目录。
- 换电脑的完整版：使用 `release/听会-0.1.2-Windows-x64-完整版` 或同名 ZIP，内含 MOSS 权重、字幕与分人组件以及独立运行环境，详见 `换电脑使用说明.md`。新电脑无需安装 Python、Node.js 或 uv。
- 从项目源码启动：双击 `启动听会.cmd`。
- 开发依赖需要重新准备时：运行 `首次安装.cmd`，需要 Node.js 22.12+ 与 uv。

语音识别凭据保存在当前 Windows 用户的 DPAPI 加密存储中，不包含在源码或发布目录里。默认数据目录为 `%LOCALAPPDATA%/MeetingStudio`，可在设置页打开。

## 日常使用

1. 点击“新建录音”或“导入录音”，选择豆包云端 / MOSS 本地。
2. 线下会议选择麦克风；线上会议选择“麦克风 + 电脑声音”，戴耳机时也需采集电脑声音。
3. 录音中可暂停、继续、收起为置顶小窗。窗口最小化不结束录音。
4. 点击说话人姓名改名；发言分错时，在该段右上方重新选择人员。文字可逐段校对，旧转写版本保留。
5. 结束或完成文件转写后查看纪要和行动项。任务负责人、日期和完成状态可以调整，每项可回到原文。
6. 导出文字 TXT、纪要 Markdown、行动项 CSV。

## 豆包配置

“设置 → 豆包语音识别”分别配置语音 Key 和识别资源。默认实时资源为 `volc.seedasr.sauc.duration`。

文件转写有三个明确的通道：

- **豆包 2.0，复用实时权限**：直接处理本机文件，不依赖 TOS，也不需要额外的文件资源权限。软件按音频的实际时长发送，例如 30 分钟录音至少需要约 30 分钟发送，再等待服务收尾，适合尚未开通文件资源的账号。依据[官方流式接口文档](https://docs.volcengine.com/docs/doubao-voice/large-model-streaming-automatic-speech-recognition-api-1?lang=zh)，不能随意加速发送。
- **文件极速版**：需要账号开通 `volc.bigasr.auc_turbo`；最长 2 小时，使用压缩后的音频直传。
- **文件标准版**：需要 `volc.seedasr.auc` 及私有 TOS 配置，通过短期签名 URL 供语音服务读取。

请使用自己的语音 Key，并按账号实际开通的识别资源选择通道。默认文件模式复用实时权限；有文件极速权限时可在设置中切换。选择云端会发送所选音频；本地模式不自动切云。

本机已准备 CAM++ ONNX 说话人辅助组件。豆包负责识别文字，辅助组件比较本机录音片段的声音特征，校正云端合并说话人的情况，不加载 MOSS 转写模型。会中先显示文字，人员标签随后补齐；证据不足的短发言保留为“待确认”，可手动分配。特征只在本机同一会议内使用，不自动跨会议认人。未安装辅助组件时使用豆包原生标签。

## 会议纪要

语音识别 Key 与文本模型 Key 是两组不同配置。

- 配置“设置 → AI 会议纪要”中的兼容接口地址、文本模型 ID 和独立 Key 后，使用该模型生成 AI 总结、决策和行动项，转写文本会发送到配置的服务。
- 尚未配置文本模型时提供**基础纪要**：从原文提取要点、明确决策及候选行动项，界面清楚标注来源，支持人工校对。基础提取不冒充大模型总结。
- 原文未明确的人员和日期不补造；检查候选行动项后再对外使用。
- 修改文字产生新版本，旧纪要保留原文证据并提示需要更新。改名会同步更新关联发言及行动项负责人。

## 本地 MOSS

源码及原轻量包的权重目录：`K:/工具箱/MOSS model/MOSS-Transcribe-Diarize`。模型代码与辅助 CAM++ 组件使用隔离环境，首次安装可运行 `安装本地模型.cmd`，或者在设置页点击准备模型。0.1.2 完整版自动使用包内的 `resources/models` 和 `resources/moss-python`，无需沿用原电脑的盘符。

源码安装首次下载约 2GB 权重，网络中断后可继续。源码及轻量包的本地运行环境单独保存，项目模式安装在 `.moss-venv`，使用它时请保留该环境及 `vendor/moss` 源码目录。完整版已将这些依赖一并打包，设置页显示随包运行环境的实际路径。

本机缺少 NVIDIA 显卡，使用 CPU。选择 MOSS 本地录音时，会中使用轻量 Paraformer 流式组件持续显示字幕，CAM++ ONNX 随后补齐人员；停止后由 MOSS 完整精修。所有这些处理均在本机执行。流式字幕为预览，可能随上下文调整，最终文字以精修版本为准。

本地流式组件位于 MOSS 权重相邻的 `auxiliary/paraformer-streaming`，约 237MB；ONNX 分人模型约 28MB。本机已准备，安装脚本会校验固定版本与文件摘要。组件不可用时会提示降级为 MOSS 分段预览，此时 CPU 延迟可能明显增加。

文件转写可后台排队，CPU 按 60 秒窗口处理、重叠 5 秒，每段完成即保存并显示文字。已修复长结果超过 64KB 导致 `Separator is not found, and chunk exceed the limit` 的进程通信错误。失败会议的原音频仍保留，可点击“重新转写”。临时人员标签不是跨会议自动认人的身份；真实多人会议仍需校对，不能承诺固定准确率。

首版本地转写固定使用 MOSS 官方标准提示词。实测自定义热词提示可能使模型漏掉时间戳，因此热词暂仅用于豆包云端；本地仍可在转写后校对人名和专业词。返回格式异常时会重试一次，仍不合规则明确报错并保留录音。

本地环境和模型已为这台电脑准备好。移动源码目录后，应重新运行本地模型安装脚本修复路径。换电脑请使用完整版并重新输入云端 Key；旧轻量包不含完整本地模型环境。完整版在保存的旧路径失效时会重新寻找包内资源。

## 开发与验证

```powershell
npm run build
.venv\Scripts\python.exe -m pytest backend/tests -q
# 前端开发，另开本地业务服务；桌面开发可设置 MEETING_DEV_URL
npm run dev
.venv\Scripts\python.exe -m uvicorn meeting_app.app:app --host 127.0.0.1 --port 9011
```

`scripts/verify-cloud.py` 是显式调用云端的集成测试，使用 Windows 合成语音，不录取真实麦克风；会产生少量调用费用。普通 pytest 测试不会调用云端。

`artifacts/` 保存非敏感联调结果，包括云端和 MOSS 两人对话、桌面录音及导出验证；不包含语音密钥。`scripts/package-portable.py` 构建带 Python 的桌面目录。具体边界和验证记录见 `交付与验证.md`。

模型、依赖、发布 ZIP、测试输出、私人会议与凭据不提交到源码仓库。自行构建时，模型下载脚本目前默认使用构建机的 `K:/工具箱/MOSS model`，完整打包脚本还引用 Visual Studio 可再分发目录；请按自己的构建环境调整。直接使用 Releases 的两个包不依赖这些构建机路径。第三方模型来源、修订和许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

当前源码版本为 0.1.2，增加完整离线依赖打包与换电脑路径恢复。已实现并联调核心流程；真实多人会议准确率、麦克风与系统声音的复杂设备组合，以及方案中的完整 30～50 场验收尚未完成。
